# Microduck：树莓派 Zero 2 W 完整迁移方案

**方案版本：R5。主控改为 Raspberry Pi Zero 2 W，保留已购15个HD-1910-C001。**

本文确定硬件路线、任务分工、接线、软件移植范围、机械修改和验收顺序。当前交付的是迁移设计与静态核对结果；软件尚未移植完成，配电PCB尚未投板，RA2模型尚未改成树莓派整机版。

## 一、最终采用的路线

| 项目 | R5选择 |
|---|---|
| 主控 | Raspberry Pi Zero 2 W，512MB，40PIN排针已焊接；不是老Zero/Zero W，也不是Orange Pi |
| 系统 | Raspberry Pi OS Lite 64-bit，无桌面；验收后锁定镜像及内核版本 |
| 存储 | 正品microSD 32GB以上，另留整卡备份 |
| 运动控制 | 本机50Hz；HD舵机后端＋独立I2C IMU；网络不参与每一帧闭环 |
| 相机 | Raspberry Pi Camera Module 2标准可见光版＋Camera Standard–Mini排线 |
| 音频 | Waveshare WM8960 Audio HAT，保留板载双MEMS麦克风 |
| 重视觉、ASR/TTS、大模型 | 电脑或云端运行，只回传高层意图/音频；不在512MB板上训练 |
| 供电 | 标准LiPo 2S；舵机原电池电压，Pi及音频走独立5V逻辑支路 |
| 定制件 | 一块PWR-PI-R5配电/TTL/保护板＋整机打印结构 |

Zero 2 W是四核64位A53、1GHz、512MB、65×30mm，具备相机接口和H.264编码能力。[主控官方规格](https://www.raspberrypi.com/products/raspberry-pi-zero-2-w/)

**这条路线有原型依据**：项目的`deploy/robotd.toml`注明，50Hz最初是在Raspberry Pi Zero 2W原型上选定的。不过当前软件已增加Rockchip专用媒体代码，且你的舵机换成了HD1910，旧原型经验不等于本机已经验收。[项目参数说明](https://github.com/pollen-robotics/microduck/blob/main/deploy/robotd.toml)

## 二、哪些功能保留，哪些处理放到外部

| 功能 | 执行位置 | 迁移后的要求 |
|---|---|---|
| 15舵机控制、姿态、跌倒检测 | Pi本机 | 固定50Hz，使用有效反馈；故障时停止使能 |
| 手柄与基础动作、离线叫声 | Pi本机 | 保留BlueZ和本地音效，不依赖网络才能站住 |
| 相机采集与视频传输 | Pi本机采集/编码 | 初版640×360、15fps、约1Mb/s，保持16:9；验证后再提高 |
| 麦克风采集、播放TTS | Pi本机音频接口 | 采用ALSA稳定卡名，初版低音量测试 |
| ToF、两处NFC交互 | Pi慢外设进程 | 独立于IMU总线和运动循环，故障不阻塞控制线程 |
| 目标识别、复杂语音理解 | 电脑/云端 | 低频图像/音频上传，返回意图；不直接发送每帧关节角度 |

远端断连时取消远程运动意图，回到本机可控状态；媒体服务崩溃不能带走控制进程。RKNN模型不在Pi上直接加载；如尝试CPU识别，必须限频并验证资源余量。该方案不宣称离线重视觉性能与RK3566版本相同。

## 三、采购清单的保留、更换与新增

### 直接保留的方向

- **HD-1910-C001：15个，新增采购0。** 原厂舵盘、壳体螺钉和线束先按已购套装复点。
- **WM8960 Audio HAT：1块。** 已取得微雪商品入口与官方尺寸资料，保留此成品路线，不再自制AIC3104音频板。
- **LSM6DSV16X IMU：1块，安装在躯干。** 龙邱模块是当前候选，要求该SKU的板框、针序与芯片实拍，排除同页LSM6DSR款。
- **VL53L8CX ToF：1块。** 优信载板是当前候选，供电/IO电平以载板电路为准，不套用Pololu模块尺寸。
- **标准LiPo 2S电池、B6neo充电器、IDEC 2NC急停**继续使用既定方向。电池实供型号、充电线和准确急停SKU仍须落实。

| 采购项 | 数量 | 规格与避免误买的重点 |
|---|---:|---|

**淘宝核验结论**：已检索到多个Pi商品入口，但一个169元混售链接实际选中的是老款ZERO，其Zero 2 W选项存在禁用标记冲突；该169元未作为2W价格写入预算。另一候选详情未完成读取。目标型号已经锁定，精确SKU价格和库存仍单独核验；不使用搜索最低价假装全套报价。

外置CMC麦克风、单独Samtec排母取消，采用HAT集成部分。套装扬声器的尺寸尚未核实，仅作为机外台架喇叭；在机扬声器按8Ω、约20mm、额定≥1W目标另核尺寸，接HAT一组BTL输出，负端不接地。

## 四、供电与保护设计

```text
标准2S电池（满电8.4V）
  └─主保险丝─┬─逻辑保险丝─逻辑欠压关断─D24V50F5─5V_LOGIC─┬─Pi
              │                                           ├─WM8960 HAT
              │                                           └─3.3V_AUX─传感器/NFC
              └─舵机受控开关─三路保险丝─每路5个HD舵机

舵机受控开关的使能条件：
硬件ARM锁存 ∧ 急停NC1闭合 ∧ 电压正常 ∧ 看门狗正常 ∧ Pi使能 ∧ 无故障锁存
```

1. **舵机电源不经过Pi、GPIO、音频HAT或调试板的细走线。** 大电流在配电板分配，控制信号共地。
2. D24V50F5是固定5V模块，典型输出能力受散热影响。官方给出的最低输入为轻载约6V、5A时约6.2V；R5逻辑支路以输入不低于6.4V为设计边界。[稳压器规格](https://www.pololu.com/product/2851/specs)
3. 5V逻辑负载按2.5A设计目标验证，3.3V辅助支路按1A容量规划；这不是已测功耗。3.3V_AUX从5V_LOGIC产生，**不与Pi的1/17脚3.3V输出并联**。
4. 初版包电压目标：6.8V预警并准备关机、6.6V停止舵机、6.4V逻辑硬截止。实际阈值需结合电池压降、精度与电芯要求复核，另做逐节欠压/失衡检测；总电压不替代逐节保护。
5. 保险丝初值沿用主15A、三路舵机各5A、逻辑输入3A，最终依电流波形、I²t、铜箔与线温确定。它们不是精确电机限流器。
6. 急停NC1进入硬件关断链；NC2只提供状态反馈。释放急停或恢复通信后仍需手动ARM，软件不得自动重使能。
7. 心跳由控制线程在完成一次受控状态机周期后产生，初版10Hz、独立硬件看门狗300ms超时为设计目标。待机时允许心跳；电机供电后另以反馈时效判断故障，避免“没反馈就不给电、没电就没反馈”的启动死锁。普通定时器不代喂。
8. 反接、短路、再生回馈及断电尖峰都需设计和波形验证。**回馈钳位器件不在缺少HD允许瞬态电压资料时随意定型**；原SMBJ12A等旧占位不自动沿用。
9. 用Micro-USB台架电源前，物理断开机内5V支路；两路5V不直接并联。充电时电池从机身取下，使用标准LiPo 2S平衡模式，而非LiHV。
10. 电机电源关闭时，TTL驱动和DATA上拉同步关闭/隔离，防止经信号线向未供电舵机反向供电。

### 上电与扭矩使能分开

`SAFE_OFF → LOGIC_READY → POWERED_CHECK → TORQUE_ENABLED`，任一故障进入锁存的`FAULT_LATCHED`。

- 待机先完成Pi、IMU、看门狗与接口检查，电机电源保持关闭。
- 手动ARM后允许电机电源进入最长1秒的上电预检窗口；**先验证HD舵机上电默认扭矩关闭**，完成ID/反馈检查并设置保持目标。资料未确认时，只在固定台架完成这项验证。
- 预检通过后，由用户再次明确使能才允许扭矩/动作；电机上电不等于开始行走。
- 超时、错ID、反馈陈旧等均关电并锁存；恢复条件后也不自动跳回使能状态。

**PWR-PI-R5仍需原理图、布局和PCBA。** 本方案没有把这块定制电源板伪装成淘宝现货，也未生成可直接投板的Gerber。

| 2、4 | — | 5V_LOGIC | Pi/HAT供电 |

| 6、9、14、20、25、30、34、39 | — | GND | 逻辑信号公共地 |
| 3、5 | 2、3 | 硬件I2C1 | IMU＋WM8960控制 |
| 8、10 | 14、15 | UART0 TX/RX | 经TTL半双工收发电路到HD总线 |
| 12、35、40、38 | 18、19、21、20 | I2S | BCLK、LRCLK、DAC数据、ADC数据 |
| 11 | 17 | HAT按钮 | 只作输入 |
| 15、16 | 22、23 | 软件I2C3 | ToF＋NFC复用器 |
| 18 | 24 | 急停状态 | NC2反馈，断线产生故障状态 |
| 22 | 25 | IMU中断预留 | 载板有INT时接 |
| 29 | 5 | 复用器RESET_N | TCA9548A复位 |
| 31 | 6 | ToF复位预留 | 载板引出LPn时接 |
| 36 | 16 | SERVO_ENABLE | 高有效设计，外部下拉，默认OFF |

### 串口与蓝牙

Zero 2 W没有原Radxa路线的UART4、UART5。采用`miniuart-bt`将蓝牙换到mini UART，释放PL011给物理8/10，使用`/dev/serial0`；固定VPU核心时钟250MHz。蓝牙吞吐会受影响，需测试手柄和BLE并行稳定性，不默认关闭蓝牙。[官方UART说明](https://www.raspberrypi.com/documentation/computers/configuration.html#configure-uarts)

HD总线目标先按1Mbps做带宽预算，但波特率、包格式和寄存器必须由本批舵机资料确认。Pi GPIO不直接当作舵机电源或任意5V总线输入；TTL接口需要方向/回波处理和电平验证。

### I2C地址与两路NFC

| 总线 | 器件 | 7位地址 | 要点 |
|---|---|---|---|
| `/dev/i2c-1` | WM8960 | 0x1A | 初始化与低频音量控制 |
| `/dev/i2c-1` | LSM6DSV16X | 0x6A或0x6B | 核芯片ID及载板跳线；固定坐标变换 |
| `/dev/i2c-3` | VL53L8CX | 0x29 | 固件加载/测距在慢外设进程 |
| `/dev/i2c-3` | TCA9548A | 0x70 | A0/A1/A2接地 |
| MUX通道0 | 头部PN532 | 0x24 | 单独通道 |
| MUX通道1 | 嘴部PN532 | 0x24 | 单独通道 |

Grove PN532默认UART，需按模块版本改为I2C；可让供货方完成跳线并验收。两个同地址设备不直接并到一条总线上。[Grove接口说明](https://wiki.seeedstudio.com/Grove_NFC/) · [TCA9548A资料](https://www.ti.com/product/TCA9548A)

MUX由Linux驱动/单一外设管理进程控制，每次只选通一个NFC通道。子总线编号通过`/sys/bus/i2c/devices/3-0070/channel-*`发现，不硬编码为i2c4/5。总线故障时先停止相关事务，再复位MUX、重建驱动状态并重新枚举，避免缓存仍以为旧通道已选中。

IMU读取在硬件总线；ToF初始低频（例如5Hz）和NFC轮询在独立软件总线。软件I2C速度需要实测；任何慢外设调用都不得阻塞50Hz控制线程。

## 六、系统配置与启动顺序

1. 用Raspberry Pi Imager选择Zero 2 W及Lite 64-bit，写入SD卡。设置Wi-Fi和SSH，不在板上安装桌面环境或编译大型依赖。
2. 先备份`/boot/firmware/config.txt`、`cmdline.txt`及整卡镜像。保留现有图形配置，仅合并附件中的配置片段。
3. 检查所选镜像是否提供`wm8960-soundcard`和`i2c-gpio` overlay；若缺少，按当前内核匹配官方/厂商支持，不混装两套音频驱动。
4. 移除`cmdline.txt`中的串口控制台项，但保持其他启动参数和单行格式；释放UART给舵机。
5. 先逻辑供电，确认音频、相机、I2C与串口，再接电机电源。整个准备阶段SERVO_ENABLE保持低。

配置核心如下；完整带注释版本见同目录文件。WM8960官方原理图中XTAL1为24MHz，而树莓派overlay默认时钟可能不同，因此显式指定并核实所发板卡。[HAT原理图](https://files.waveshare.com/upload/f/fa/WM8960_Audio_HAT_Schematic.pdf) · [官方overlay参数](https://raw.githubusercontent.com/raspberrypi/firmware/master/boot/overlays/README)

```ini
dtparam=i2c_arm=on
dtparam=i2c_arm_baudrate=400000
dtparam=i2s=on
enable_uart=1
dtoverlay=miniuart-bt
core_freq=250
dtoverlay=i2c-gpio,bus=3,i2c_gpio_sda=22,i2c_gpio_scl=23,i2c_gpio_delay_us=2
dtoverlay=wm8960-soundcard,alsaname=wm8960,mclk=24000000
camera_auto_detect=1
```

控制心跳与使能GPIO由移植后的控制状态机独占；普通定时器或媒体进程不代喂看门狗。I2C复用器需在慢总线注册，随后枚举子总线；其驱动绑定与故障恢复属于外设进程的实现工作。

## 七、软件迁移任务清单

| 现有位置 | R5要做的改动 | 验证方式 |
|---|---|---|

| `duck-control/src/imu.rs`及`io.rs` | 增加LSM6DSV16X I2C/SFLP FIFO读取，接入原`ImuData`；删除对ID200同步应答的依赖 | 轴向、量纲、四元数归一化、陈旧样本与断线测试 |
| `robotd-params`、`deploy/robotd.toml` | 增加Pi板型配置；串口`/dev/serial0`、ALSA`plughw:wm8960`；配置版本可追踪 | 解析及往返测试，保留旧平台配置兼容性 |
| `mediad/src/pipeline.rs`、`producer.rs`、`exposure.rs` | 增加Pi媒体后端，替换rkisp/MPP及Rockchip曝光逻辑；使用libcamera/rpicam与Pi硬件H.264 | 独立视频测试，再集成WebRTC、音频与控制 |

| `kinematics`及媒体帧元数据 | 重标Camera Module 2内参、裁剪后的视场及相机到头部的安装变换 | 重核坐标旋转，不盲用旧90°旋转或Radxa相机标定 |
| `duck-detect`、`pet-detect` | 默认关闭板端重识别；使用电脑/云端服务，或另做低频CPU模式 | 验证超时不会阻塞机器人，远端只下发高层意图 |
| `tof`与新NFC外设进程 | 使用慢I2C3、MUX子总线、有限超时；媒体和运动读取缓存结果 | 模块掉线/总线锁死时IMU与控制继续满足时序 |

| `scripts/setup-board.sh`等部署脚本 | 新增Pi配置分支，不运行Radxa的rsetup、rkisp/NPU安装；ARM64依赖在电脑上构建 | 独立Pi发布通道、签名/哈希/健康检查和回滚测试 |

**当前源码的默认相机质量、串口和音频设备仍偏向Radxa。只改串口路径不足以让HD舵机和相机工作。**已有`.rknn`不在Pi加载；ONNX运动策略保持本地，但舵机、质量、惯量和安装改变后仍须辨识/再训练或验证。现有51维/61维策略也须按运行时接口检查。

先单独用`rpicam`证明Camera Module 2的硬件采集/编码，再接WebRTC。初版640×360、15fps不写成已达成性能；它需要新质量档位和真实媒体后端。[Pi相机软件](https://www.raspberrypi.com/documentation/computers/camera_software.html)

## 八、机械模型修改清单

| 部位 | 必做事项 |
|---|---|

## 九、按阶段执行，避免反复改方案

## 十、验收目标与失败处理

以下数值是本方案的工程验收目标，不是已测结果或官方保证：

- 控制目标50Hz，30分钟并发测试中平均≥49Hz、周期p99≤25ms；记录总线错误和最长停顿。
- 连续无有效电机/IMU反馈超过100ms进入失能处理；独立看门狗覆盖控制线程完全卡死。
- 内存`MemAvailable`保留至少80MB目标，不持续换页；先限媒体/识别负载，不通过压低保护要求掩盖性能不足。
- CPU持续温度目标低于75°C，记录降频/欠压标志；Pi输入端5V测试目标4.85–5.20V。
- 检查15个ID、转向、零位、关节限位和角度/速度/电流量纲；舵机总线不是Dynamixel寄存器表的简单重命名。
- 验证急停按下、线断、断电重启、故障恢复：电机默认OFF，释放急停后不自动启动；Pi逻辑电源保持到正常关机或低压硬截止。
- 验证ToF/MUX/NFC故障不会锁住实时IMU路径；网络/媒体失联只影响远端功能，不替代本机故障保护。
- 先悬挂、单关节/单腿，再受控地面运动；旧策略不因文件能加载就视为适配HD电机。

如果Zero 2 W在上述任务分工下仍达不到控制时序或内存目标，先收缩本地媒体/识别负载并保留远端处理；仍不满足时进入明确的Pi更高配主控评审，而不是继续采购并假定能跑。
